# AI 科普双平台内容生产方法论

本文概括一套面向批量创作的公众号与小红书内容生产流程。具体阶段指令、字段结构和脚本用法以 [`aike-公众号流`](../../skills/aike/aike-公众号流/SKILL.md) 为准。

## 目标与原则

- 从有来源的素材出发，批量产出公众号文章和小红书笔记，并共享选题、事实核验与视觉资产。
- 以批次为最小生产单元：统一规划、并行写作、集中渲染、逐篇检查、汇总发布。
- 每篇保留来源与加工记录；不编造事实、数据或引用；观点和原素材要区分清楚。
- 使用固定结构和视觉模板提升一致性，同时按内容类型选择语气、版式与配色。
- 外部账号凭证只保存在本地配置中；发布动作和平台登录由使用者控制。

## 批次状态与目录

每个批次放在项目根目录的 `批次/批次-<批次号>/` 下，含批次编排表和若干 `NN-<slug>/` 文章目录。单篇目录通常包括：

- `article.md`：公众号稿件；
- `xhs-note.md`：独立编写的小红书笔记；
- `article.yaml`：标题、作者、摘要和发布状态等元数据；
- `render.json`：封面和卡片模板、配色及字段；
- `imgs/`：渲染后的封面与卡片；
- `发布清单.txt`：发布前信息与素材顺序。

原始素材保存在单独的素材目录，按类别和主题整理。批次稿件引用或复制素材时，保留来源 URL 与必要元数据。完成并发布后，按归档脚本规则移动批次及已使用素材，避免重复使用。

## 生产阶段

1. **规划选题**：确定受众问题、内容价值、平台适配与批次顺序，形成编排表。
2. **收集素材（G1）**：读取来源链接，抓取正文与元数据，按科普、观点、工具、技术、金句等类别归档；失败项单独记录，不阻塞其他素材。
3. **加工素材**：提炼事实、关键观点、可操作步骤和引用来源；判断是否适合改写，并记录需要进一步核实的内容。
4. **双平台改写（G2）**：公众号稿按固定文章结构解释问题并给出可执行步骤；小红书稿重新组织成短钩子、要点、互动和标签，避免直接截短长文。逐篇按写作标准自检。
5. **批量配图**：根据段落信息选择封面母版和卡片类型，将内容字段写入 `render.json`，用本地 HTML 模板批量截图生成素材，减少重复的图片 API 调用。
6. **排版与平台稿生成**：公众号稿转为兼容 HTML，注入对应栏目皮肤；同时生成卡片图文版。小红书使用独立笔记正文并按顺序准备封面和卡片。
7. **总审（G3）**：汇总每篇标题、事实与来源、平台格式、图片顺序、元数据和发布状态；使用者集中审核并逐篇提出修改。
8. **发布、归档与复盘**：按发布清单处理公众号草稿和小红书手动发布；更新批次状态，归档来源素材，记录失败、返工和可复用经验。

## 质量门

- **G1 素材门**：来源可追溯，正文有效，分类与主题合理；无法确认的内容标为待核实。
- **G2 改写门**：观点不走样，结构清楚，术语有解释，步骤可执行，文字自然；双平台内容各自适合平台。
- **G3 发布门**：稿件、元数据、HTML、图片尺寸与顺序、来源、标题和发布清单完整；发布前确认目标平台及发布方式。

脚本检查用于发现缺文件、格式错误或不完整产物；内容事实与发布许可仍需人工审核。

## 分工与并行

主控负责批次编排、统一标准、脚本串行执行和总审；写作子任务只处理分配的文章目录，产出约定文件并报告状态。渲染、收尾、归档等会读写共享目录的脚本由主控串行执行。具体协作边界见 [`多 AI 协作协议`](multi-agent-protocol.md)。

## 复用与本地配置

将本仓库的 `skills/aike/` Skills 安装到 Agent 的 Skill 目录，并在项目根目录保留 `render/` 与 `风格/` 资源。按需安装 Python、Pillow、Node.js、无头浏览器及微信 HTML 转换工具。模型 API、公众号凭证、代理地址和工具可执行文件路径通过个人环境变量或本地配置提供，不写进公开仓库。
