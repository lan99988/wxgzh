# 多 AI 协作协议（本地文件夹版）

> 适用：多个 AI（WorkBuddy 多 agent、多个独立会话、外部 AI 工具）在项目根目录内**同时协作**完成内容生产。
> 原则：**文件系统即通信**——不靠口头/记忆，靠「编排表 + 目录状态 + 日志文件」传递事实。
> 冲突成本最高的是「两人同时改同一篇/同一阶段」，本协议围绕消灭它设计。
> 版本：v1.0（与统一批次设计配套）

---

## 1. 三条铁律（违规 = 丢工作）

1. **编排表是唯一事实源** —— 动任何任务前先读该批 `批次编排表.md`；完成后必须回写。绝不在编排表之外自建进度记录。
2. **认领即加锁** —— 同一任务（一篇 / 一个阶段）同时只允许一个 AI 持有。未认领不许开工，干完必须释放。
3. **发布/归档整批串行** —— `publish.py` 与 `archive_used.py` 一次只允许一个 AI 执行，其他 AI 不得并发触碰同一批次。

---

## 2. 单一事实源：批次编排表

- 每批一份：`批次\批次-YYYYMMDD\批次编排表.md`（过渡期：`审核\批次-YYYYMMDD\批次编排表.md`）。
- 每篇一行，列为：篇 / slug / 素材 / 类型 / ①选题 / ④改写 / ⑤配图 / ⑥排版 / ⑦总审 / ⑧发布。
- **状态集合**：`未开始` → `进行中@<AI名>` → `待确认` → `已确认` / `打回`。
- 认领写法：把目标单元格从 `未开始` 改为 `进行中@<名字>`（例：`进行中@AI-1`）。
- `check_batch.py <批次号>` 输出**文件系统实态**（不读编排表），是唯一客观校验，以它为准。

## 3. 任务认领与释放（锁协议）

| 步骤 | 动作 |
|---|---|
| 1 读 | 读编排表 → 找 `未开始` 或 `打回` 的任务 |
| 2 认领 | 目标单元格改 `进行中@<你的名字>` + 写下开始时间 |
| 3 干活 | 只动自己认领的篇目录/素材，不碰他人目录 |
| 4 完成 | 状态改 `待确认`（等用户总审）或直接 `已确认`（用户已放行）→ 释放 |
| 5 打回 | 用户打回某篇 → 状态回 `打回` → 原认领者优先重做（24h 内），超时任何 AI 可接管 |

**锁定规则**：
- **篇级锁**：一篇的 ④⑤⑥ 由同一 AI 连续做完（改写→配图→排版强依赖），中途不换手。
- **素材锁**：素材领用 = 目录改名 `制作中-<素材名>`（沿用现有机制），改名即锁定。
- **批级锁**：阶段①选题规划、⑦总审汇总、⑧发布、素材归档 = 整批串行，由**批次主理 AI** 执行。

## 4. 并发分工模型（推荐）

```
批次主理 AI（1 个）          创作 AI（N 个，并行）
├─ 阶段① 选题规划（串行）     ├─ 各领 2~3 篇，逐篇走 ④⑤⑥（篇级并行）
├─ 阶段② 素材收集（可并行，按类别分片）
├─ 阶段⑦ 总审汇总（串行）
├─ 阶段⑧ 发布 + 归档（串行）  └─ 打回重做：谁认领谁负责
└─ 编排表维护（全程）
```

- **推荐粒度**：批次主理 AI 负责状态机与对外汇报；创作 AI 只认领篇目，全程无交叉。
- **并行上限**：同一批次最多 N 个创作 AI（每篇独占），互不干扰。

## 5. 互斥操作清单（整批串行，一次一人）

| 操作 | 命令 | 为何互斥 |
|---|---|---|
| 公众号发布 | `publish.py full <目录>` | 频率限制 + 草稿箱顺序 |
| 素材归档 | `archive_used.py <批次号>` | 移动/删除素材，幂等但并发会乱 |
| 批次移动 | 批次目录 rename（在办→待发布→已发布） | 结构变更，他人路径全失效 |
| 草稿清理 | `draft/delete` | 删错不可逆 |

> 互斥操作前：编排表状态标 `进行中@<名字>(发布)`；其他 AI 看到该标记立即退出该批发布相关操作。

## 6. 冲突检测与解决

1. **认领前必重读编排表**（不要用旧缓存）——发现目标已是 `进行中@他人` → 换任务。
2. **双重检查**：认领时同时看目录（素材是否已 `制作中-`、文章文件夹是否已存在且非空）。
3. **撞车后**：后到者放弃并记录到批次 `协作日志.md`，不覆盖他人产物；由先到者完成。
4. **写文件纪律**：只写自己认领篇的目录；编排表/协作日志用「读-改-写」且改后立即回写，避免互相覆盖。
5. **结果以文件实态为准**：两个 AI 对同一篇认知不一致时，跑 `check_batch.py` 用客观结果裁决。

## 7. 通信与日志

- **批次级日志**：`批次\批次-YYYYMMDD\协作日志.md`（过渡期：`审核\批次-YYYYMMDD\协作日志.md`），append-only，格式：
  ```
  [T+00:00] AI-1 认领 03-xxx 改写 → 进行中@AI-1
  [T+00:30] AI-1 完成 03-xxx 改写 → 待确认（check_batch 全绿）
  ```
- **发布记录**：每篇 `article.yaml` 写 `media_id` / `publish_id` / `publish_completed`（发布 skill 的既有字段）。
- **交接**：AI 中断/退出前，把未完成任务状态回写编排表（保持 `进行中@<名字>` 或回 `未开始`），并在协作日志留一行说明——他人可无缝接管。

## 8. 幂等与重跑（防沙盒/网络抖动）

- 脚本全部可安全重跑：`init_batch.py`（骨架幂等）、`render_batch.py`（覆盖渲染）、`check_batch.py`（只读）、`archive_used.py`（按元数据 url 去重，重跑不双份）。
- 命令被沙盒拦截自动重跑 = 无害；但**涉及移动/删除的操作用 `--dry-run` 先看**。

## 9. 快速自查（开工前 10 秒）

- [ ] 我读的是最新编排表？（重读确认）
- [ ] 我要做的任务没有 `进行中@他人`？
- [ ] 素材/文章目录未被锁定（`制作中-` 前缀）？
- [ ] 我有没有在跑发布/归档类互斥操作？
- [ ] 完成后我会回写编排表 + 协作日志？
